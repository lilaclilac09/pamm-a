What is an AMM?

You're about to build a market-making robot. Let's understand what that actually means.

Markets need someone to make prices

🏦

Traditional Exchange

Buyers and sellers post limit orders. A centralized order book matches them when prices cross. Requires active human market makers.

🤖

Automated Market Maker

A AMM uses a mathematical formula to quote prices 24/7. No humans needed — just math and liquidity.

When you trade on Uniswap or any DeFi exchange, you're not matched with another human. You're trading directly against a pool of tokens managed by an AMM formula.

The classic constant-product AMM demands that reserve_x × reserve_y always equals the same number k. This single rule determines every price the AMM quotes.

// How many Y tokens do you get for Δx tokens of X?
// Before: rx × ry = k
// After:  (rx + Δx) × ry_new = k
output_y = ry − (k / (rx + Δx))
output_y = (ry × Δx) / (rx + Δx)
// Bigger input → bigger output, but with diminishing returns

Price emerges from the ratio

The spot price of token X in terms of Y is just reserve_y / reserve_x. When the pool has 1,000 X and 2,000 Y, one X costs about 2 Y. No oracle needed — the ratio is the price.

Before Trade
X=1000, Y=2000
Price = 2.00 Y/X
Someone Buys 100 X
Pays ≈ 182 Y
Price impact: paid 1.82/X avg
After Trade
X=900, Y=2182
Price = 2.42 Y/X

That price increase is not a bug — it's a feature. Large buyers pay more, which deters excessive single trades and ensures the AMM always has tokens to sell. The curve is concave by design.

The starter code, decoded

This is the actual Rust you start with. It implements a basic constant-product AMM with a 5% fee. Let's read it line by line.

CODE 

pub fn compute_swap(data: &[u8]) -> u64 {
  let decoded = wincode::deserialize(data);
  let input = decoded.input_amount as u128;
  let rx    = decoded.reserve_x    as u128;
  let ry    = decoded.reserve_y    as u128;
  let fee_input = input * 9500 / 10000;
  ((ry * fee_input) / (rx + fee_input)) as u64
}
PLAIN ENGLISH

The function receives the full market state as raw bytes and returns how many tokens to give out.

Decode the bytes into a struct with input_amount, reserve_x, reserve_y fields.

Unpack the input amount and both reserves into 128-bit integers to avoid overflow.

Charge a 5% fee: multiply input by 9500/10000, so only 95% of the input counts toward the swap.

Apply the x*y=k formula using the fee-adjusted input. Return as a 64-bit integer.

Your challenge: replace this formula with something smarter. The fee, the shape of the curve, even the state you track — all of it is under your control. The next modules explain what "smarter" means.
